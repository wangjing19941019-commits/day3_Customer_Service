# 智能客服系统 · 设计风格

status: Confirmed  
适用平台：Web 桌面端（内部使用）  
本次界面：登录、员工端、客服端、知识库、管理端工单列表、管理端模板  

**依据**：已确认 PRD（REQ-001～REQ-011）、已确认 `docs/tech-spec.md`（2026-09-23）。旧客服端三列仍沿用；本轮补工单四态颜色、润色对比、知识溯源、管理端列表与模板。视觉方向不改，只加页面。  
**基准视口**：1440×900；适配 1280～1920。窄于 1024 时侧栏改为顶栏下的横排导航，对话与列表改为上下堆叠，客服工作台（表单/知识）叠在对话下方，输入区仍钉在当前对话面板底部。  
**关键选择依据**：内部同事长时间对着文字工作，优先可读、状态清楚、少装饰；客服信息更密，对话与工单分区，不让表单挤掉回复输入。

## 一、设计目标与风格判断

### 产品类型与体验目标

内部电商智能客服网页。同一套账号进入三个工作面：用户侧提问、坐席接管填单、知识维护。最常做的是在员工端把购物问题说清楚并得到回答；最需要看清的是「现在是谁在回、会话有没有转人工、工单是草稿还是已确认、这篇知识有没有入库完」。体验目标：员工能连续读写而不丢输入区；客服打开就能分清会话、表单与可推送知识；知识库一眼看出入库中 / 可用 / 请重新上传。

业务范围见 PRD，不在此增加能力。

### 视觉风格

名称：**冷静工作台**。浅灰画布、白表面、一条沉稳蓝作主操作，状态用语义色加点而不是大色块。避免营销渐变、插画背景、过圆消费风、深色炫光。

| 判断 | 取舍 |
| --- | --- |
| 任务 | 主区给当前对话或当前文档；导航只占左侧窄条 |
| 阅读 | 对话气泡限宽、长文换行；改写记录用弱样式附在原问下 |
| 布局 | 登录居中卡片；登录后顶栏 56px + 侧栏 220px + 内容区 |
| 约束 | 键盘为主；等待用按钮内文字和列表状态，不用全屏遮罩挡住返回 |

### 关键 UX 规则

1. **主操作只有一个（按区域）**：登录是「登录」；员工未转接是「发送」，已转接仍是「发送」。知识库主操作是「上传」；文档已完成时主操作是「保存标签和 FAQ」。客服对话区主操作是「发送」；工单区主操作是「确认工单」（未选售后类型时禁用）。润色是输入区次按钮，不代替发送。
2. **状态写在对象上**：入库中、请重新上传、等待客服，直接标在文档行或对话顶栏，不只靠 Toast。
3. **错误可接着做**：登录失败留在表单且保留用户名；上传失败文案固定为「请重新上传」；发送失败保留输入框文字。
4. **长内容滚中间、钉两端**：消息列表滚动，顶栏与输入区不滚走；知识库上传条与左列筛选钉住，文档列表滚动；客服左列表与右对话分区各自滚动。
5. **隐藏页不占位**：侧栏互斥，同一时刻只渲染当前页。

### 字体与字阶

| 用途 | 字体与回退 | 字号 | 字重 | 行高 / 字距 |
| --- | --- | --- | --- | --- |
| 页面标题 | `"Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif` | 20px | 600 | 28px / 0 |
| 区块标题 | 同上 | 16px | 600 | 24px / 0 |

### 布局、间距与形状

- 间距刻度：4 / 8 / 12 / 16 / 24 / 32px。
- 登录卡：宽 400px，内边距 32px，垂直居中。
- 登录后：顶栏高 56px；侧栏宽 220px；内容区内边距 24px。
- 员工端：消息区占满剩余高度，输入条高自适应、最小 88px（含按钮行）。
- 客服端：左列 320px 会话列表；中列对话；右列 360px 工作台（业务线、工单类型、表单、知识推送）。中间 1px Border。对话输入钉在中列底部。
- 知识库：上条上传 64px；左列 320px，列顶筛选条钉住、下列表滚动；右侧详情至少 520px（窄屏改为列表下方），内含只读分块预览，分块区独立滚动。
- 控件高：输入 40px，主按钮 40px，次按钮 40px，列表行最小 56px。
- 圆角：卡片/对话框 8px，按钮/输入 6px，气泡 12px（员工右下、系统左下直角 4px 以区分方向）。
- 窄屏：侧栏改为顶栏下方横排，高度 48px；客服改为上列表（40vh）→ 中对话 → 下工作台，输入仍钉在对话面板底。

### 层次、阴影与动效

- 顶栏与侧栏用 Border 与 Canvas 区分，不用重阴影。
- 登录卡：`0 8px 24px rgba(31, 41, 51, 0.08)`。
- 下拉/错误条：`0 4px 12px rgba(31, 41, 51, 0.08)`。
- 动效仅按钮色 120ms、状态点呼吸（入库中 1.2s 循环）。其余保持静态。提供 `prefers-reduced-motion: reduce` 时取消呼吸。

## 四、界面清单与页面设计

索引：UI-01 登录 · UI-02 员工端 · UI-03 客服端 · UI-04 知识库。共用外壳（登录后）：顶栏左侧「智能客服」+ 当前页名，右侧「已登录：用户名」+ 次按钮「退出」；侧栏三项。原型：`docs/prototypes/01-login/index.html`、`02-employee/index.html`、`03-agent/index.html`、`04-knowledge/index.html`。

### UI-01 登录

- **依据与目标**：REQ-004 / AC-009、AC-010、AC-026。用唯一账号进入系统，或作为未登录/已退出后的停留页。原型：`docs/prototypes/01-login/index.html`。
- **布局结构**：无侧栏。Canvas 满屏，居中 Surface 卡。阅读顺序：标题 → 「当前未登录」→ 说明 → 用户名 → 密码 → 登录 → 失败说明。
- **内容呈现**：单列，标签在字段上方。
- **组件清单**：

| 区域 | 组件类型 | 内容/数据 | 交互表现 | 全局风格引用 |
| --- | --- | --- | --- | --- |
| 卡头 | 页面标题 | 智能客服 | 静态 | 20px/600 |
| 状态 | 辅助信息 | 当前未登录 | 静态 | TextMuted |
| 说明 | 辅助信息 | 使用统一账号进入员工端、客服端和知识库 | 静态 | TextMuted |
| 表单 | 文本输入 | 用户名、密码 | 密码掩码；错误保留用户名 | 输入五态 |
| 操作 | 主按钮 | 登录 | 提交中禁用 | 主按钮 |

- **状态与操作结果**：
  - 空表 → 点登录 → 字段下提示必填，不进入系统。
  - 填错密码 → 点登录 → 本页 Danger 文案「用户名或密码不正确」，不跳转。
  - 正确 → 进入员工端（UI-02），顶栏右侧显示「已登录：用户名」和「退出」。
  - 从业务页点退出 → 回到本页「当前未登录」。
- **示例数据与文案**（仅演示）：用户名 `it-help`，密码不在界面回显。失败文案见上。
- **页面例外**：无。

### UI-02 员工端

- **依据与目标**：REQ-001、REQ-003 及相关 AC；REQ-004 / AC-025、AC-026。提问、看回复、点转人工；顶栏可见登录态并可退出。原型：`docs/prototypes/02-employee/index.html`。
- **布局结构**：外壳 + 主区。顶栏右侧固定「已登录：用户名」与「退出」。主区自上而下：会话状态条（未转接 / 已转人工等待客服）→ 消息滚动区 → 输入区（textarea + 发送 + 转人工）。阅读顺序：登录态 → 状态 → 历史消息（含改写）→ 输入。窄屏输入仍钉底。
- **内容呈现**：员工右、其他左。原问下用辅助信息展示改写。知识回答在同一气泡内用分段标题（如「1. …」「2. …」），不是两条系统消息。
- **组件清单**：

| 区域 | 组件类型 | 内容/数据 | 交互表现 | 全局风格引用 |
| --- | --- | --- | --- | --- |
| 顶栏右侧 | 辅助 + 次按钮 | 「已登录：用户名」、退出 | 点退出丢弃登录态并回登录页 | 次按钮 |
| 状态条 | 辅助 + 次按钮 | 「AI 接待中」或「已转人工，等待客服」 | 未转接可点转人工 | 次按钮 |
| 消息区 | 气泡列表 | 员工/FAQ/反问/知识/兜底/客服 | 新消息追加并滚到底 | 气泡 |
| 输入 | 多行输入 + 主按钮 | 问题原文 | 空内容点发送无效；发送中禁用 | 主按钮「发送」 |

- **状态与操作结果**：
  - 空会话 → 辅助句「描述你的购物问题」。
  - 发送含糊问法 → 系统反问气泡（未满 5 轮）。
  - 满 5 轮仍不清 → 固定兜底原文。
  - 命中 FAQ / 知识 / 闲聊 → 对应标签气泡。
  - 点转人工 → 状态条改为已转人工，转人工按钮禁用；再发送只出现员工气泡，无系统自动回；客服回复稍后出现在左侧气泡。
  - 刷新（演示：同标签页）→ 仍是同一会话，顶栏仍显示已登录用户名。
  - 点退出 → 回到登录页「当前未登录」；未再登录不能使用本页。
- **示例数据与文案**（仅演示）：员工「这件连衣裙能退吗」；改写「询问该连衣裙是否支持退货」；知识「服饰美妆支持七天无理由退货，需商品完好」。兜底用 PRD 原文。
- **页面例外**：用户气泡使用白字，仅此页。

### UI-03 客服端

- **依据与目标**：REQ-003、REQ-005～REQ-008 / AC-005、AC-006、AC-008、AC-030～AC-043；REQ-004 / AC-025、AC-026。处理已转人工会话：对话、工单草稿确认、知识推送、润色后发送。原型：`docs/prototypes/03-agent/index.html`。
- **布局结构**：外壳顶栏右侧「已登录：用户名」与「退出」。左会话列表 320px；中列完整对话 + 底部输入（润色次按钮 + 发送主按钮）；右列工作台 360px，自上而下：业务线、工单类型、表单与确认、知识推送。无会话时中列与右列空状态。阅读：登录态 → 列表 → 对话 → 工作台 → 输入。确认工单与发送回复分属两个区域，不并排两个同级主按钮。
- **内容呈现**：列表行两行：首行员工最后一句摘要（单行截断），次行「已转人工」。对话含改写记录。字段四态必须能区分，沿用已有状态色，不新造色板：已填用 Success，低置信候选用 Warning，缺失和冲突用 Danger，旁边写中文「已填 / 待确认 / 缺失 / 冲突」。低置信显示候选但不算已填。订单号多条时列出候选，不预选。抽取中在表单顶显示「正在根据对话补全…」，不挡住整页。知识卡片含主答案、摘要、来源、生效时间、适用品类，只给坐席看，没有「发给用户」按钮。润色通过时在输入区上方对比原稿和润色稿，可选采用、修改或放弃；不通过时只显示 Danger 合规风险，不能直接采用。
- **组件清单**：

| 区域 | 组件类型 | 内容/数据 | 交互表现 | 全局风格引用 |
| --- | --- | --- | --- | --- |
| 顶栏右侧 | 辅助 + 次按钮 | 「已登录：用户名」、退出 | 点退出回到登录页 | 次按钮 |
| 左列 | 列表行 | 已转接会话 | 点击选中 | 列表行 |
| 中列消息 | 气泡 | 完整链路 | 只读历史 | 气泡 |
| 中列输入 | 多行 + 次按钮 + 主按钮 | 拟发送内容 | 润色改输入区预览，不发出；发送把当前文本写入对话 | 次按钮「润色」；主按钮「发送」 |
| 工作台 | 下拉 + 表单 + 主按钮 | 业务线、类型、字段 | 未选售后四类时「确认工单」禁用；确认后类型不可改，字段仍可手改 | 主按钮「确认工单」 |
| 知识区 | 只读卡片 | 政策/步骤/标准答案 | 可忽略；无相关时写明没有可推送依据 | 卡片；辅助 12px |

- **状态与操作结果**：
  - 无已转接会话 → 「还没有需要人工处理的对话」。
  - 员工已转接 → 列表出现该会话；工作台为空草稿。
  - 手选业务线（3C / 服饰，可改）→ 知识区换成对应口径。
  - 选择售后四类之一 → 表单出现该类型字段；先显示「正在根据对话补全…」，数秒后预填或标待补全（D-006=B）。坐席手改后不被后一次预填盖掉。
  - 不选类型（售前）→ 不能确认工单；仍可润色和发送。
  - 点确认工单（已选类型且已选手选业务线）→ 状态变为「已确认」；之后不再自动预填（D-007=A）；仍可手改字段和业务线。
  - 润色 → 输入区出现整理后的稿，员工端尚无该条；发送后员工端出现发出的文本。
  - 知识推送不出现在员工对话里。
- **示例数据与文案**（仅演示）：摘要「这件连衣裙能退吗」；退换货表单订单号待补全、商品「连衣裙」；知识「服饰美妆七天无理由退货」。客服发送「已帮你核对退货条件，请补充订单号。」
- **页面例外**：左列 320px，右列 360px；窄屏列表 40vh，工作台在对话下方。

### UI-04 知识库

- **依据与目标**：REQ-002 / AC-003、AC-004、AC-017、AC-018、AC-023、AC-024、AC-027、AC-028、AC-029；REQ-004 / AC-025、AC-026。上传 Markdown、TXT 或能抽出文字的 PDF，按最近更新浏览文档、按入库状态筛选、查看真实分块结果、维护标签与 FAQ；顶栏可见登录态并可退出。原型：`docs/prototypes/04-knowledge/index.html`。
- **布局结构**：上条：文件选择 + 上传（主操作，不放筛选）+ 一行辅助说明「支持 Markdown、TXT，以及能抽出文字的 PDF」。主区：左列自上而下为筛选条 + 文档列表（列表单独滚动，筛选钉在列顶）；右详情。已完成文档的详情自上而下：切块策略说明 → 只读分块列表（序号、标题路径、正文）→ 可改标签与 FAQ → 保存。入库中/失败不可进入分块与编辑。分块列表在详情内滚动，长块正文换行。
- **内容呈现**：阅读顺序：上传说明 → 筛选（当前状态）→ 列表行（**原文件名** → 状态点+中文状态 → 本地时间；完成后可加「N 块」）→ 详情。文件名过长截断、悬停出全名；扩展名保持上传时的 `.md` / `.txt` / `.pdf`，不改成转换后的 `.md`。时间用 12px TextMuted，本地时区，到分钟即可（如「9月14日 00:10」），不显示秒、不显示 `created_at`。状态用「入库中 / 已完成 / 请重新上传」。分块序号从 1 起；无标题时标题路径为空不显示冒充标题。标签用对象/诉求中文名。
- **组件清单**：

| 区域 | 组件类型 | 内容/数据 | 交互表现 | 全局风格引用 |
| --- | --- | --- | --- | --- |
| 顶栏右侧 | 辅助 + 次按钮 | 「已登录：用户名」、退出 | 点退出回到登录页 | 次按钮 |
| 上传条 | 文件选择 + 主按钮 + 辅助说明 | `.md` / `.txt` / `.pdf` | 不支持的格式、空文件、抽不出文字的 PDF 立刻「请重新上传」，不进列表 | 主按钮「上传」；说明 TextMuted 12px |
| 筛选条 | 四个单选胶囊 | 全部 / 入库中 / 已完成 / 请重新上传 | 默认「全部」；点一项只看该状态；可换行 | 筛选胶囊 |
| 列表 | 列表行 | 原文件名、状态、时间、分块数（完成后） | 按最近更新倒序；入库中不可打开详情编辑 | 状态点；时间 TextMuted 12px |
| 分块预览 | 只读卡片列表 | 序号、标题路径、正文 | 不可编辑、无保存分块按钮 | 正文 14px，辅助 12px |
| 编辑 | 标签 + FAQ + 主按钮 | 对象/诉求、问与答 | 保存后立即变；不重切分块 | 主按钮「保存」 |

- **状态与操作结果**：
  - 打开页面 → 列表最新在上；行上能看到原文件名、状态和时间。
  - 点筛选 → 只显示对应状态；某一状态没有文档 → 「当前没有该状态的文档」，上传条仍可用。无任何文档且筛「全部」→ 「还没有知识文档。请上传 Markdown、TXT 或能抽出文字的 PDF。」
  - 上传合法 `.md` / `.txt` / 能抽出文字的 `.pdf` → 该条出现在列表最前，状态「入库中」并带当前时间；若当时筛的是「已完成」或「请重新上传」，筛选自动回到「全部」。无分块预览；后台先转 Markdown 再按策略切块后变为「已完成」，详情展示全部实际分块。
  - 上传不支持的格式、空文件、或抽不出文字的 PDF → 立刻「请重新上传」，列表不出现该条。
  - 后台失败 → 「请重新上传」，无分块、无 FAQ。
  - 保存标签/FAQ → 分块正文不变，提示已立即用于后续提问。
- **示例数据与文案**（仅演示）：策略句「所有格式先转为 Markdown；按 Markdown 标题与段落切块，单块不超过 800 字，块间重叠 160 字（上限的 20%）；有标题时保留标题路径，没有则路径为空。」演示列表同时有 `outlook.md`（入库中）、`vpn-faq.md`（已完成，有标题多块）、`wifi-reset.txt`（已完成，无标题）、`scan-only.pdf`（请重新上传），便于点四个筛选并对照原文件名。
- **页面例外**：左侧列表列仍 320px；筛选条在列内换行，不把左列加宽。右侧详情宽 560px，供分块正文阅读。上传条可换行，辅助说明不抢主按钮。已完成文档在标签下增加可见范围（用户可见 / 仅坐席可见 / 高风险仅人工）和政策生效起止时间，保存用次按钮，不新造主色。

### UI-06 管理端模板

- **依据与目标**：REQ-009。管理身份按业务线、工单类型、场景编辑模板，预览代入结果，看版本差异、灰度和回滚。坐席没有入口。

## 五、使用与验收

**应采用**：状态写在行上；输入区钉底；改写附在原问下；三个导航互斥；文案用业务名；确认工单与发送回复分开。  
**应避免**：全屏 Loading 挡住知识库离开；用弹窗代替入库失败；客服列表出现未转接会话；把 `fallback`、`handed_off` 直接显示给用户；润色后不点发送就把稿发给用户；未选工单类型仍显示可点的确认。

文档检查：四页均有布局、组件、状态与示例；色值与字阶只在第二节定义；长文本、空态、窄屏已说明。

**原型验证**（阶段 B）：本环境无可用浏览器自动化工具，未能打开原型做视觉与交验收。未验项：1440 与窄屏实机画面、滚动与输入区钉底、登录/提问/转人工/填单确认/润色发送主流程的点击结果。源码已按互斥导航、状态文案和分区主按钮组织；不能把文件存在视为视觉通过。用户确认前请在浏览器中打开下列页面操作：

- `docs/prototypes/01-login/index.html`（当前未登录；错误密码、正确密码 it-help / it-help123）
