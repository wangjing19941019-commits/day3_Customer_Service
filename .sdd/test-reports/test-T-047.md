## 发现并修复的产品缺陷

1. **管理端看不到坐席反馈（AC-062）**：`metrics()` 的 `feedback_summary` 写死为「暂无回流问题」。改为按模板汇总 `result_feedbacks`：总数、无用数、最近 3 条（目标、评价、说明、版本）。文件 `backend/src/services/templates.py`，单测 `test_feedback_shows_in_admin_metrics_of_its_template`。
2. **润色丢掉原稿金额（AC-050，T-046 留下的观察）**：费用争议原稿「主张 200 元、核算 120 元」，润色稿只剩 120。`polish.md` 要求原稿中每个时效、金额、政策名称都要出现且数值不变；`check_compliance` 新增「润色稿删掉了原稿中的金额」，命中后不能采用。单测 `test_compliance_rejects_dropped_draft_amount`。
3. **售前润色被加上退换货说法（AC-052）**：首轮探针 2/5 出现「可按服饰类商品常规退换货规则处理」。根因是 `line_apparel_beauty.md` 写着「使用服饰美妆退换货口径」，而且该文件与填单抽取共用，不能直接改。改为润色在未选类型时，把类型标为「售前咨询（未建工单）」，并加一条售前边界；`polish.md` 加对应规则。修复后 0/5。单测覆盖提示词内容。
4. **轻快原稿在愤怒会话里被保留「亲，」（AC-051 体验）**：合规已拦截、不能采用，但坐席只能放弃。`polish.md` 的愤怒规则补「去掉亲、哈哈、哦、啦、~ 等，称呼用您」，修复后 0/5 轻快。

另外，自查时发现第 2 步把金额检查插在 `if new_amounts` 和 `elif 高风险赔付` 之间，打断了原来的分支。已恢复原分支，删金额检查改为独立判断。

## 脚本问题（非产品缺陷）

- 第 1 轮 AC-051 失败：坐席发出回复后会话列表重新排序，脚本按列表位置点选，两次「愤怒」润色实际打到退货会话。改为点选后核对该会话的知识推送请求，不对就刷新重选；润色前再核对请求的会话 id。直接用 API 对愤怒会话重复 3 次，均被正确拦截，说明后端规则本身无误。
